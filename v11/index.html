Why residential proxies

          
The attacker that looks like your customer.

          
Credential stuffers and account-takeover crews no longer log in from data centers. They rent traffic through millions of hijacked home routers and phones, so every attempt arrives from a normal ISP in a normal city. Blocklists and geo rules wave it through.

          
whereami answers one narrow question very well: is this IP a residential proxy right now? It’s a building block, not an auth provider and not a black-box score.

How it works

        
One lookup after the password check.

        
Your auth flow stays exactly as it is. Add a single call, and write the rule that fits your app.

        

          

            
01
Send the IP

            
Pass the IP address of the login attempt. That’s the only required field.

            
sl.whereami({ ip: req.ip })

          

          

            
02
Get one signal

            
A yes or no on residential proxy, a confidence value, and the ISP it exits through.

            
{ residential_proxy: true,
  confidence: 0.98 }

          

          

            
03
Apply your rule

            
Step up to MFA, slow the attempt, or just log it. Your call.

            
if (r.residential_proxy) requireMfa()

FAQ
Questions developers ask.

        

          
Is this an auth provider or a risk score?
Neither. whereami answers one question: is this IP a residential proxy? Keep your auth provider, and combine the signal with your own rules.

          
What should I do when it returns true?
Most teams step up to MFA or email verification. Some rate-limit, some only log. A residential proxy on its own isn’t proof of fraud, so we leave the decision to you.

          
How fast is it?
Median response is about 12 ms, fast enough to run inline before you issue a session.

          
Can an AI agent sign up by itself?
Yes. Accounts, keys, payment, and spend caps all work through the API. Point your agent at llms.txt.

          
What if I want to leave?
Delete your key. There’s no contract, and the API is plain REST, so nothing in your code depends on us beyond one call.

# securityLab

> Modular, pay-as-you-go security APIs for developers and AI agents.
> Not an auth provider. Each tool answers one question; you decide what to do.
> Accounts, keys, payment, and spend caps can be managed entirely via API.

## Products
- whereami: is this IP a residential proxy? Status: available.
- breached: has this password appeared in a breach (k-anonymity)? Status: planned.
- disposable: is this a burner email domain? Status: planned.

## whereami
- Endpoint: POST https://api.securitylab.dev/v1/whereami
- Auth: Authorization: Bearer $SL_KEY
- Input: {"ip": "91.240.118.172"}
- Output: residential_proxy (bool), confidence (0-1), isp, country, first_seen, last_seen
- Accuracy: 0.98 precision, 0.94 recall. Latency: 12 ms median.
- Price: 1,000 lookups/month free, then $0.40 per 1,000

## Sign up (agent-friendly)
1. POST /v1/accounts {"email": "...", "monthly_cap_usd": 20}
2. Complete payment via returned checkout_url or a payment token
3. Use returned api_key as SL_KEY

## Integration guidance
Call whereami after primary authentication succeeds and before issuing a session.
If residential_proxy is true, apply the app's own policy (e.g. require a second factor).

## Terms
No contract, no minimum, cancel any time. Volume pricing is automatic.
