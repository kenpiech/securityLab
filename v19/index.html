whereami · background

Why residential proxies matter

Credential stuffing and account takeover used to come from data centers, which are easy to block. Now attackers rent access to millions of real home connections through proxy networks. Their logins arrive from ordinary ISPs, in the right country, one attempt per address.

That traffic slips past the defenses most apps rely on:

Data-center blocklists
Miss it

The IP belongs to a home ISP, not a hosting provider.

Geo rules
Miss it

Attackers pick exits in your users’ own country.

whereami
Catches it

We observe proxy networks directly and see which home IPs they route through.

whereami · quickstart

Quickstart

Add whereami after your existing password or magic-link check, before you issue a session. Once you have a key, it takes about five minutes.

  1. Request access

    Join the early access list. When your spot opens you get a key, by email or through the API, with 1,000 free lookups a month.

  2. Install the SDK

    npm install @securitylab-placeholder/node or pip install securitylab-placeholder. Or call the REST endpoint directly.

  3. Look up the login IP

    Pass the client IP. You get back residential_proxy and a confidence.

  4. Decide in your code

    Step up to MFA, slow the attempt down, or log it. The policy is yours.

whereami · reference

Response

Every lookup returns the same small object. No scores mixed from signals you can’t see.

FieldTypeDescription
residential_proxybooleanThe IP was observed relaying traffic for a residential proxy network.
confidencenumber0 to 1. How sure we are of the answer above.
ispstringThe home ISP the address belongs to.
countrystringISO country code of the exit.
first_seendateWhen we first saw this IP in a proxy network.
last_seendatetimeMost recent observation. Proxy exits churn; recency matters.
Try itSample data only · no request is sent
