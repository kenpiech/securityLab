# securityLab

> NOTICE: This is a design prototype for a class assignment. securityLab, its API, packages,
> endpoints, and prices do not exist. Do not sign up, install, or call anything described here.

> Pay-as-you-go authentication security APIs. No contract, no sales call.
> Accounts, keys, payment, and spend caps can be managed entirely via API.

## Products
- whereami: login-time risk scoring from IP + metadata. Status: available.
- whoami: device/client consistency signals. Status: beta.
- last: account history anomalies. Status: coming soon.

## whereami
- Endpoint: POST https://api.securitylab.example/v1/whereami
- Auth: Authorization: Bearer $SL_KEY
- Input: ip (required), user_agent, account_id, timestamp
- Output: risk (0-1), action (allow | challenge | deny), signals[], location
- Latency: 18 ms median
- Price: 1,000 checks/month free, then $0.40 per 1,000 (placeholder price)

## Sign up (agent-friendly)
1. POST /v1/accounts {"email": "...", "monthly_cap_usd": 20}
2. Complete payment via returned checkout_url or payment token
3. Use returned api_key as SL_KEY

## Integration guidance
Call whereami after primary authentication succeeds and before issuing a session.
If action == "challenge", require a second factor. If "deny", reject and log.
