01 — The problem

A login that passes every check.

Here’s a sign-in your system sees every day. The password matches. The IP belongs to a major US cable provider, in the same state as your customer. No data-center range, no Tor exit, nothing on a blocklist.

ACCOUNTjordan@acme-shop.com
PASSWORD✓ Correct
IP ADDRESS91.240.118.172 · Comcast Cable · Ohio, US
BLOCKLISTS✓ Not listed
ACTUALLYAn attacker using a leaked password, routed through a stranger’s home router

This is how most account takeovers now arrive. Attackers rent access to residential proxy networks: millions of real home connections, often hijacked through malware or sketchy free apps. Their traffic exits from ordinary consumer IP addresses, so it slips past data-center blocklists and country rules built for an older kind of attack.

02 — What whereami does

One question. One field.

whereami tracks the exit IPs of residential proxy networks as they rotate. Give it an IP address and it tells you whether that address is currently relaying proxy traffic, with a confidence and the network it belongs to.

Is this IP a residential proxy? → "residential_proxy": true

That’s deliberately all it does. It isn’t a login risk score, and it doesn’t make decisions for you. It’s a sharp, well-measured signal you plug into the logic you already have.

05 — Modular by design

Small tools, not a platform.

securityLab builds single-purpose security tools that each do one job well and compose with everything else you run. whereami is the first. Each one is its own small API, priced by the call, with nothing to migrate onto and nothing to migrate off.

No lock-in. It’s plain REST with JSON responses, plus thin SDKs and an MCP server. If you stop using it, you delete a few lines of code. There’s no contract to unwind.
