DESCRIPTION

          

            
whereami reports whether an IP address is a residential proxy: a hijacked device on a real customer’s home connection that attackers rent so their traffic looks like your users. Call it at login, after the password check and before you issue a session.

            
Credential stuffing used to come from data centers, which are easy to block. Now it arrives from ordinary ISPs, in your users’ own country, one attempt per address. Data-center blocklists and geo rules miss it. whereami watches proxy networks directly and knows which home IPs they route through.


attacker            holds a list of stolen passwords
   │
   │ rents exits
   ▼
proxy network       millions of home IPs for hire
   │
   │ relays via
   ▼
hijacked device     on a real customer’s home connection   ◀ whereami flags this IP
   │
   │ logs in as
   ▼
your login          sees an ordinary home user

            
securityLab makes small, single-purpose security tools. whereami is not an auth provider and does not return a risk score or a verdict. It returns one signal; your code keeps the decision. Plain REST, no contract, no lock-in.

          

        


        

          
REQUEST

          

            

              
ip string, required

              
The client address of the login attempt. IPv4 or IPv6.

              
Authorization header, required

              
Bearer $SL_KEY. Keys are scoped per project, capped, and revocable.

            

          

        


        

          
OUTPUT

          

            
Every lookup returns the same small object. No hidden scoring.

            

              
residential_proxy boolean
The IP was observed relaying traffic for a residential proxy network.

              
confidence number
0 to 1. How sure we are of the answer above.

              
isp string
The ISP the address belongs to.

              
country string
ISO country code of the exit.

              
first_seen, last_seen date, datetime
When we first and most recently saw the IP in a proxy network. Exits churn; recency matters.

BUGS

          

            
Mobile carrier addresses are not flagged, by design: carrier NAT puts many real users behind one IP.

            
Proxy exits churn daily. A brand-new exit can take hours to appear; check last_seen before treating an old true as current.

            
False positives happen. Report them and we’ll look at the evidence with you.
