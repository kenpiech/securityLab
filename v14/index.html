Why residential proxies

        
The attacks that look exactly like your users.

        
Data-center IPs are easy to block. So attackers rent access to hijacked home connections instead, and their credential-stuffing traffic arrives from ordinary-looking Comcast, Vodafone, and Jio addresses.

        
    
          
  1. Blocklists miss them. The IPs belong to real ISPs and rotate constantly.
    2. 
          
  2. Geo rules miss them. Attackers pick exits in your users’ own city.
    3. 
          
  3. whereami sees them. We track proxy networks directly and flag their exit IPs as they appear.
    4.

Integrate

        
One call, one field, your rules.

        
Check the IP after the password succeeds and before you issue a session. What happens next is up to you: ask for MFA, slow things down, or just log it.

        
    
          
  • Works beside Clerk, Auth0, Supabase, Auth.js, or your own login
    • 
          
  • REST, Node and Python SDKs, and an MCP server
    • 
          
  • Plain JSON in and out, so you can leave whenever you like
    • 
        

      

      

        
login.tsNode.js


import { SecurityLab } from "@securitylab/node";
const sl = new SecurityLab(process.env.SL_KEY);

// after the password check succeeds
const r = await sl.whereami({ ip: req.ip });

if (r.residential_proxy && r.confidence > 0.9) {
  return requireMfa(user);   // your call
}
